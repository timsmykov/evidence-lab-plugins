# Language and writing contract

Use one language for all human-readable prose in a task card.

1. An explicitly requested output language wins.
2. Otherwise, a Russian request produces a Russian title, description, result, acceptance criteria, rationale, and report.
3. An English request produces those fields in English.
4. For mixed input, use the language of the actual task request, not the quoted source material. If still ambiguous, use the dominant language and state the choice.
5. Keep product names, code, commands, identifiers, URLs, file paths, established acronyms, and canonical workspace option values unchanged.

Load Writing Skill before drafting and use its business-writing route: lead with the result, use concrete verbs and named actors, and remove filler. Then run Humanizer in the same language and register. Humanizer must not alter facts, scope, dates, roles, canonical values, or acceptance criteria.

Avoid lexical hybrids that insert an English process word into otherwise Russian prose when a clear Russian equivalent exists. Keep English only for actual product names, identifiers, code, commands, file names, or established technical terms that would lose precision in translation.
