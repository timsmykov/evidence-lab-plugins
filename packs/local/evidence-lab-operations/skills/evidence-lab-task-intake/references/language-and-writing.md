# Language and writing contract

Use one language for all human-readable prose in a task card.

1. An explicit requested output language wins.
2. Otherwise, a Russian request produces a Russian title, description, result, acceptance criteria, rationale, and report.
3. An English request produces those fields in English.
4. For mixed input, use the language of the actual task request, not the language of quoted source material. If still ambiguous, use the dominant language and state the choice.
5. Keep product names, code, commands, identifiers, URLs, file paths, established acronyms, and canonical database option values unchanged.

Load Writing Skill before drafting. Use its business-writing mode: answer first, concrete verbs, explicit owner and action, no vague corporate filler. Then run Humanizer as an editorial check. Do not let Humanizer alter facts, scope, dates, roles, field values, or acceptance criteria.

Avoid lexical hybrids that insert an English process verb or noun into otherwise Russian prose when a clear Russian equivalent exists. A technical term may remain English when it is the actual product or system term, but the surrounding sentence stays in the chosen language.
