# example-procedure

Показывает форму скилла-процедуры: где решает человек, где рассуждает модель и где работает скрипт. Предметной методики здесь нет — реальный плагин ставит на это место процедуру, выведенную из чьей-то практики.

## Когда применяется

- На входе есть набор документов и нужен структурированный свод по ним.
- Пользователь готов подтвердить промежуточное решение — набор признаков, по которым строится свод.

## Когда не применяется

- Нужно найти новые источники, а не обработать имеющиеся.
- Артефакт уже готов и его надо проверить — это `example-checklist`.
- Спрашивают, как устроен метод, а не просят его выполнить.

## Кто что делает

| Шаг | Кто выполняет | Артефакт |
|---|---|---|
| 1. Разобрать входной набор | модель | список документов с типом и объёмом |
| 2. Предложить признаки для свода | модель | черновик набора признаков |
| 3. Подтвердить признаки | исследователь | утверждённый набор |
| 4. Извлечь значения по признакам | модель | `extracted.json` |
| 5. Собрать таблицу | скрипт `scripts/build_table.py` | `summary.md` |
| 6. Проверить результат | субагент `example-domain-critic` | список замечаний |

Шаг 5 намеренно отдан скрипту: сортировка, выравнивание колонок и подстановка в шаблон обязаны давать одинаковый результат при повторе. Если такой шаг оставить модели, свод будет каждый раз слегка другим, и сравнить два прогона станет нельзя.

## Процедура

1. Прочитай входной каталог и составь перечень документов. Файлы, которые не удалось прочитать, вынеси отдельным списком — молча пропускать нельзя.
2. Предложи 4–7 признаков для свода и коротко обоснуй каждый.
3. **Точка подтверждения.** Покажи набор признаков и дождись решения исследователя. Не продолжай на молчании: подобранные моделью признаки — это гипотеза, а не результат.
4. Извлеки значения по утверждённым признакам в `extracted.json`; там, где значения в документе нет, ставь `null`, а не догадку.
5. Запусти `python3 scripts/build_table.py extracted.json --out summary.md`.
6. Передай `summary.md` субагенту `example-domain-critic` и приложи его замечания к результату.

## Формат результата

`summary.md` по шаблону `templates/report.md`: таблица, явный охват (сколько документов обработано, сколько не прочиталось), список пропусков.

## Гейты качества

- Каждая строка таблицы прослеживается до конкретного документа.
- Пропуски показаны как пропуски, а не заполнены правдоподобным текстом.
- Признаки утверждены человеком до извлечения, а не подогнаны под результат.
- Повторный запуск на том же `extracted.json` даёт побайтово тот же `summary.md`.

## Границы

- Не оценивает качество самих источников.
- Не заменяет решение исследователя о том, что считать существенным.
